## ⬜ Задачи за бэкендом / хостингом (Блок E)

### E1. HTTPS + HSTS
- [ ] Принудительный HTTPS, редирект `http → https` (301).
- [ ] Заголовок `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`.

### E2. HTTP-заголовки безопасности
- [ ] `Content-Security-Policy` (разрешить свой домен, `mc.yandex.ru`, `smartcaptcha.yandexcloud.net`,
      `api-maps.yandex.ru`; шрифты теперь только `self`).
- [ ] `X-Frame-Options: SAMEORIGIN` (или `frame-ancestors 'self'` в CSP).
- [ ] `X-Content-Type-Options: nosniff`.
- [ ] `Referrer-Policy: strict-origin-when-cross-origin`.

### E3. `form-handler.php` (Bitrix)
- [ ] **Серверная** проверка токена Yandex SmartCaptcha (`smart-token`) через API проверки —
      не доверять только клиентской капче.
- [ ] Валидация и экранирование всех входных полей (имя, телефон, город, должность, сообщение и т.д.).
- [ ] Rate-limiting / антиспам (ограничение числа заявок с одного IP за период).
- [ ] **Сохранять вместе с заявкой:** `consent_version`, `consent_timestamp` (из формы), IP-адрес,
      User-Agent, серверную метку времени и идентификатор принятого документа — чтобы доказать
      факт, время и редакцию согласия (ст. 9 ФЗ-152).
- [ ] Ограничение прав доступа к сохранённым заявкам (только уполномоченные сотрудники).
- [ ] Логирование доступа к заявкам.

### E4. Хранилище заявок
- [ ] Шифрование доступа к данным (как минимум доступ по защищённому каналу, разграничение прав).
- [ ] Разграничение прав доступа (роли).
- [ ] Регулярные бэкапы, **физически расположенные в РФ**.

### E5. Локализация БД в РФ (ст. 18 ч. 5 ФЗ-152)
